ITIC Five Cup

A web app for pre-registering to the five-a-side soccer tournament between the BTS 1 and BTS 2 classes, with a secure admin area for the student union (BDE).

Context

The ITIC Paris student union (BDE) runs the ITIC Five Cup, a five-a-side soccer tournament between two classes: BTS 1 and BTS 2. It needed a tool to collect players' pre-registrations and put the teams together.

A first prototype existed, but data only lived in memory, the admin password was checked in the browser, and exporting registrations was still just planned. This project turns it into a complete application: a React front end, a Node.js/Express API and an SQL database.

Problem

Every student had to be able to sign up in one of three ways, without creating an account:

  • Solo: the student union then finds them a team.
  • By joining a team from their class: the captain accepts or declines the request.
  • As captain: they create the team and approve their own teammates.

The admin area and players' personal data also had to be protected, and a team could never go over its maximum size, even if two players were approved at the same moment.

Approach

  • Architecture: a single repository with three folders, client (React/Vite front end), server (Express API) and database (SQL scripts), started together in development.
  • Database: three tables (event, teams, participants), a schema.sql script for the structure and a seed.sql script with dummy test data.
  • Sign-up flow: players pick their class, then how they want to take part. Instead of accounts, the app uses secret random links: captains get one to accept or decline requests, players get another to follow up on theirs.
  • Security: admin password checked on the server, JWT session in an httpOnly cookie, rate-limited login attempts, server-side validation with Zod, personal data never returned by the public API, and a CSV export protected against Excel formula injection.
  • Data consistency: team size is checked inside an SQL transaction with a lock, so a team can never go over its limit.
  • Student union area: dashboard, editing of the date, venue and price, canceling registrations, closing and reopening teams, recovering a captain's link, and CSV export.
  • Deployment: in production, the Express server can serve both the API and the front end on the same port on any Node host. The live version runs on Vercel, after moving the database from MySQL to PostgreSQL (Neon).

Result

The app is live and its code is public on GitHub. Students can pre-register solo, with friends or as a captain, and the student union tracks registrations and teams from its admin area.

Still to be finalized: the official logo and tournament visuals, plus the GDPR notices and data retention period, which need to be approved by the school.

This project let me build a complete application, from the database schema to deployment, and put into practice securing an admin area, server-side validation and handling concurrent requests with SQL transactions.
