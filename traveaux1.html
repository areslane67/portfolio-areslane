Gestion du personnel des ligues (M2L)

Faire évoluer une application Java en ligne de commande, utilisable par une seule personne, vers une application multi-utilisateur avec base de données, trois niveaux de droits et interface graphique.

  • Java
  • JDBC
  • MySQL
  • Tests unitaires
  • Interface graphique
  • MCD
Voir le code

Le besoin

Un responsable de la Maison des Ligues (M2L) utilise une application pour gérer les employés des ligues. Elle ne fonctionne qu'en ligne de commande et par une seule personne à la fois. L'objectif : désigner un administrateur par ligue, chargé de recenser les employés de sa ligue.

  • Employé : consulte l'application comme un annuaire, sans droit d'écriture.
  • Administrateur de ligue : gère les employés de sa propre ligue depuis une application de bureau.
  • Super-administrateur : modifie tous les employés et gère les comptes des administrateurs en ligne de commande.

Déroulé en 4 itérations

Itération 1

Modélisation et tests

  • Modélisation de la base de données avec un MCD
  • Tests unitaires pour vérifier le bon fonctionnement de l'application
  • Gestion des dates d'arrivée et de départ de chaque employé
  • Arbre heuristique des menus en ligne de commande
Itération 2

Base de données et menus

  • Création de la base de données
  • Gestion des dates dans les menus en ligne de commande
  • Sélection d'un employé avant de pouvoir le modifier ou le supprimer
  • Changement de l'administrateur d'une ligue
Itération 3

Connexion JDBC et maquettes

  • Classe fille de Passerelle pour gérer la connexion à la base avec JDBC
  • Maquettes de l'interface graphique
Itération 4

Interface graphique et déploiement

  • Interface graphique pour que les administrateurs gèrent leur ligue
  • Une ligue sans administrateur est gérée automatiquement par le compte root (avec tests unitaires)
  • Installation de la base sur un serveur du réseau local
  • Rédaction d'un mode opératoire pour les administrateurs
